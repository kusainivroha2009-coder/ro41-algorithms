# Альтернативная трассировка массивов (Задание 6)

Исходный массив: `a = {4, 1, 7, 3, 9}` (всего элементов `n = 5`).

---

## 1. Сдвиг влево на одну позицию (сохранение a[0] в буфер)

**Алгоритм:** Запоминаем `temp = a[0]`, циклически сдвигаем элементы влево через цикл `while` или `for`, на последнюю ячейку записываем значение из `temp`.

* **Старт:** `temp = 4`

| Номер шага | Индекс i | Массив после выполнения шага | Комментарий |
| :---: | :---: | :--- | :--- |
| **Инициализация** | — | `{4, 1, 7, 3, 9}` | Значение `a[0]` скопировано в буфер (`temp = 4`) |
| **Шаг 1** | 0 | `{1, 1, 7, 3, 9}` | `a[0] принимает значение a[1]` (единица) |
| **Шаг 2** | 1 | `{1, 7, 7, 3, 9}` | `a[1] принимает значение a[2]` (семь) |
| **Шаг 3** | 2 | `{1, 7, 3, 3, 9}` | `a[2] принимает значение a[3]` (три) |
| **Шаг 4** | 3 | `{1, 7, 3, 9, 9}` | `a[3] принимает значение a[4]` (девять) |
| **Завершение** | — | `{1, 7, 3, 9, 4}` | В ячейку `a[4]` записывается `temp` |

**Результат сдвига:** `{1, 7, 3, 9, 4}`

## 2. Разворот массива на месте

**Логика:** Перестановка элементов зеркально: меняем местами элементы с индексами `i` и `n - 1 - i`. Цикл идет до середины массива ($\lfloor n / 2 \rfloor$). При $n = 5$ граница равна $2$ (происходят итерации при $i = 0$ и $i = 1$).

| Шаг | Индекс i | Какие элементы меняются | Массив после операции обмена |
| :---: | :---: | :---: | :--- |
| **Старт** | — | — | `{4, 1, 7, 3, 9}` |
| **Шаг 1** | 0 | `a[0]` и `a[4]` (значения 4 и 9) | `{9, 1, 7, 3, 4}` |
| **Шаг 2** | 1 | `a[1]` и `a[3]` (значения 1 и 3) | `{9, 3, 7, 1, 4}` |

* **Всего совершено обменов:** **2**.
* **Почему цикл ограничен `n / 2`:** Обмен происходит сразу парами (симметрично с обоих концов). Если делать цикл до конца массива, то элементы поменяются во второй раз и вернутся на свои исходные места, отменив результат. Центральный элемент при нечетной длине остается на месте сам по себе.

## 3. Ошибка в поиске минимума при `min = 0`

### Пример массива для демонстрации ошибки:
`a = {4, 1, 7, 3, 9}` (или любой массив, где все числа строго больше нуля).

### В чем заключается проблема:
Если переменная `min` изначально равна `0`, а элементы массива положительные, то проверка `a[i] < min` (например, `4 < 0`) всегда будет давать ложный результат. В итоге алгоритм выдаст ошибочное значение `0`, хотя нуля в самом массиве нет.

### Как правильно исправить инициализацию:
* **Вариант для поиска значения:** Присваивать в качестве начального минимума первый элемент массива:  
  `int min = a[0];` (а цикл начинать со следующего индекса `i = 1`).
* **Вариант для поиска индекса:** Инициализировать нулем именно индекс элемента:  
  `int minIndex = 0;`
