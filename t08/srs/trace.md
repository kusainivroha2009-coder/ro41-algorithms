# Отчёт: Анализ строк, парсинга и динамики памяти в C#

## Раздел 1. Обработка пробелов и разделение строки
Рассматривается исходная строка `s = "  Ахметов Ерлан;85 "`.

* **Действие метода Trim():** Очищает краевые символы-пробелы. Итоговая строка выглядит как `"Ахметов Ерлан;85"`, а общая длина уменьшается с 19 до 17 единиц.
* **Результат разбиения через Split(';'):**
  * Элемент массива под индексом `0`: подстрока `"Ахметов Ерлан"`, её размер составляет 13 символов.
  * Элемент массива под индексом `1`: подстрока `"85"`, её размер составляет 2 символа.

## Раздел 2. Проверка корректности числового парсинга (`int.TryParse`)
Для строки `line = "Иванов Пётр;70;85;x"`, разделенной по разделителю `;`:

1. Элемент `"Иванов Пётр"` (позиция 0): Конвертация невозможна из-за букв и пробела. Результат `TryParse` — **false**, выходной параметр `out` получает значение `0`.
2. Элемент `"70"` (позиция 1): Успешный разбор. Результат `TryParse` — **true**, в параметр `out` записывается число `70`.
3. Элемент `"85"` (позиция 2): Успешный разбор. Результат `TryParse` — **true**, в параметр `out` записывается число `85`.
4. Элемент `"x"` (позиция 3): Ошибка преобразования. Результат `TryParse` — **false**, выходной параметр `out` сбрасывается в `0`.

*Общий итог работы `TryParseScores`:* Метод вернёт **false**, поскольку в структуре данных обнаружены нечисловые элементы (на нулевой и третьей позициях).

## Раздел 3. Выделение памяти: `string` против `StringBuilder` (цикл от 0 до 3)

| Подход / Инструмент | Механизм работы в памяти | Итоговое количество объектов |
| :--- | :--- | :---: |
| **`string` с оператором `+=`** | Строки неизменяемы. Каждое объединение порождает новый экземпляр в куче (heap). | **5 объектов** (1 пустой на старте + 4 за итерации цикла) |
| **`StringBuilder` с методом `.Append()`** | Задействует внутренний изменяемый буфер, обновляя данные без выделения новых строк. | **1 объект** (сам экземпляр `StringBuilder`) |

## Раздел 4. Особенности неизменяемости типа `string` (`ToUpper()`)
Тип данных `string` в платформе .NET является **иммутабельным** (строго неизменяемым после инициализации). Вызов метода `s.ToUpper()` физически не может изменить старый участок памяти — он формирует и возвращает **новый** объект строки в верхнем регистре. Если не записать этот результат обратно в переменную (`s = s.ToUpper();`), то указатель продолжит ссылаться на первоначальный неизменённый фрагмент.
